# 初版流程草案：多租户商品展示与外部渠道跳转

状态：待产品确认。本文定义初版目标流程，不代表现有代码已经按此运行。

## 产品定位

Omnilink 初版是多商家共用的商品发现与品牌展示平台。商家在自己的组织和店铺下维护商品资料，选择是否公开到店铺页和 Omnilink 发现页。消费者查看商品与价格，再跳转至商家提供的小红书、抖音等外部页面继续交易。Omnilink 初版不承接下单、支付、库存扣减、发货、售后或数字商品交付。

## 参与者与边界

- 平台账户：登录 Omnilink 的用户；可加入一个或多个组织。
- 组织：租户和数据隔离单位，拥有成员、商品、渠道配置。
- 店铺：组织面向消费者的公开身份与展示页。初版保留组织下多个店铺的结构，商品是否出现在哪个店铺需显式指定。
- 商品：可被发现的内容与价格信息，不等同于 Omnilink 可履约的销售单元。
- 外部渠道链接：商家为商品维护的目标页面。初版支持小红书、抖音；数据结构允许日后增加其他渠道。

## 商家主流程

1. 注册或登录，创建组织与店铺，填写店铺名称、简介和公开资料。
2. 创建商品草稿：至少填写名称、封面、简要说明、展示价格与币种。若同一商品存在不同规格且价格不同，应明确展示价格的适用规格或价格区间。
3. 添加一个或多个外部渠道链接。每条链接包含平台、目标 URL、可选渠道展示价及可选说明。商家确认链接指向自己可负责的商品或内容页面。
4. 预览公开卡片和详情页，检查价格说明、渠道名称及跳转目标。
5. 发布到指定店铺；商家另行决定是否同步进入 Omnilink 发现页。发布条件是商品资料完整且至少有一条可用的外部链接。
6. 商家可修改价格、替换链接、暂停某条渠道或下架商品。下架后公开入口应停止展示，旧链接不再作为有效商品详情呈现。

## 消费者主流程

1. 从 Omnilink 发现页或商家店铺页进入商品详情。
2. 查看图片、商品信息、展示价格、价格说明及可用渠道。
3. 选择小红书或抖音等渠道，看到清楚的按钮文案，例如“前往小红书查看”。点击后进入商家设置的目标页面。
4. 外部页面负责后续咨询、下单、支付与履约。Omnilink 不生成订单，也不承诺外部价格、库存或交易结果。

## 价格与链接规则

- 商家维护 Omnilink 展示价格。它是展示信息，不作为成交价或结算依据。
- 若各渠道价格不同，在对应渠道入口旁展示渠道价；没有渠道价时展示商品的基础展示价。价格文案应说明实际价格以目标平台页面为准。
- 没有准确价格时，允许“价格待确认”或“询价”，但不得用 `0` 冒充真实售价。这类商品是否允许发布，需要产品确认。
- 对规格价格不一致的商品，初版优先展示“¥最低价起”或明确的价格区间，不能把某个规格价当成整件或整套价格。
- 外部链接由商家输入，发布前校验格式、协议和平台归属。是否可访问可做辅助检查，但不因目标平台阻止自动访问就误判为失效。按钮文案明确标出外部平台；商家发现链接失效后可暂停该入口。
- 同一个商品可有多个渠道入口；不自动把一个渠道链接改写成另一个平台的链接。

## 初版页面与状态

| 页面 | 初版职责 |
| --- | --- |
| 商家商品列表 | 草稿、已发布、已下架状态；显示展示价格、已配置渠道和公开范围。 |
| 商品编辑页 | 编辑资料、展示价格、渠道链接与发布范围；提供预览。 |
| 店铺公开页 | 只展示该店铺已发布商品及店铺信息。 |
| Omnilink 发现页 | 只展示商家明确开放到发现页的商品，保留店铺归属。 |
| 商品详情页 | 展示商品信息、价格说明和外部渠道入口。 |

空状态：没有渠道链接的商品保留为草稿；某渠道失效时仍可使用其他有效渠道；所有渠道失效时公开详情页暂停跳转并提示商家处理。加载和保存失败需有明确反馈。

## 与现有实现的差距

- 现有数据库已经有组织、店铺、商品、规格、销售渠道和店铺商品绑定，可保留多租户骨架。
- 当前 `catalog_item_channels.is_purchasable`、商品发布接口和公开页购买按钮仍按站内购买语义工作，需要调整为“可展示 + 可外跳”。
- 现有购物车、结账、订单确认和询盘路径不应出现在初版消费者主流程中；已保存的订单数据不因本次定位变更而直接删除。
- 现有小红书、抖音能力主要是渠道文案生成，尚未形成商品级外部目标链接的完整管理与公开读取链路。
- README、后台导航、店面文案及旧设计文档仍描述站内交易，实施时需统一产品口径。

## 待确认的产品决策

1. Omnilink 发现页是否默认收录商家已发布商品？本草案建议单独开关，由商家显式选择。
2. 没有可核实数字价格的商品，是否允许用“询价”发布？本草案建议允许，但必须有有效外部链接。
3. 外部链接以商品为单位，还是初版就要求每个规格分别配置？本草案建议先按商品配置；若规格对应不同目标页，再增加规格级覆盖。

以上三项确认后，再拆分数据库变更、商家后台、公开页面和历史交易入口的实施任务。
