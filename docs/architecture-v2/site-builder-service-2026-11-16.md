# 建站服务实现记录

日期：2026-11-16。承接 `site-builder-phase1-2026-11-16.md` 的数据合同与源码边界。

## 交互

商家在 `/dashboard` 的现有输入框提交建站要求，例如“帮我创建网站，首页突出商品图片”。识别网站意图后进入网站上下文，后续“改成两列”等指令继续修改当前网站；关闭网站上下文后恢复普通工作台输入。网站任务卡显示实际持久化任务及取消入口。

`/dashboard/storefront` 只负责展示。支持首页、商品列表和商品详情预览、版本选择、桌面/手机宽度、刷新、发布、回滚和取消发布。所有设计输入返回工作台，不增加第二个聊天框。预览及历史版本指向同一个店铺网站。

商家设置中的 DeepSeek API Key 入口复用现有加密 HttpOnly Cookie 机制。建站固定调用 DeepSeek，不读取其他供应商的 Key，不在数据库持久化用户 Key。

## 服务流程

1. 身份和商家资格校验，检查请求来源、输入合同、用户 Key 和 Sandbox 配置。
2. 数据库原子预留任务。每个店铺只有一个网站、一个活动构建；请求 UUID 支持重试去重，基线版本检查避免覆盖并发修改。
3. 读取授权店铺的商品 DTO 和已有源码，通过 DeepSeek 返回受限文件变更集。
4. 固定版本依赖在隔离 VM 安装，安装完成关闭网络，再执行 TypeScript 检查和 esbuild。源码只能写页面、组件和样式，不能修改 SDK、依赖、入口和执行命令。
5. 成功后保存源码、产物、摘要和版本，再更新草稿指针。失败、取消和超时不替换已发布版本。旧任务结果通过 revision 校验拒绝写入。
6. 预览以独立 Sandbox 域名运行 SSR 与 hydration，带短期访问凭据及 CSP；不在主应用域执行生成代码。预览刷新读取最新授权商品 DTO。
7. 发布只移动线上版本指针，保留发布记录。公开运行时通过固定的公开商品 API 获取当前数据，不接收预览中的草稿商品。公开入口为 `/sites/{storeSlug}`，未发布返回 404。

## 数据和权限

迁移：`supabase/migrations/20261116072939_ai_website_builder.sql`，已应用到当前开发项目。

- `ai_websites`：店铺 ID 主键及草稿/发布指针。
- `ai_website_builds`：生成状态、版本、源码、产物、运行租约和错误。
- `ai_website_releases`：发布、回滚和取消发布记录。

三表启用 RLS，客户端不能调用管理 RPC，也不能直接读源码、产物和预览凭据。服务端 RPC 再校验实际组织成员权限。发布仅限 owner/admin。运行租约按网站、构建和模式区分；失效实例按租约条件清除，避免覆盖新实例。

## 配置和运行边界

- 服务端需要 Supabase service role 配置。
- Sandbox 支持短期 `VERCEL_OIDC_TOKEN`，或 `VERCEL_TOKEN`、`VERCEL_TEAM_ID`、`VERCEL_PROJECT_ID` 三项认证。短期 Token 到期后需要刷新；不提交真实凭据。
- `SITE_DATA_ORIGIN` 必须为部署了 `/api/site-data/v1` 的可信 HTTPS origin。发布前检查接口可达性和数据版本。未配置或不可达时不允许发布。
- 任务通过 Next.js `after()` 执行，生成预算 120 秒，隔离构建最多 150 秒，路由 maxDuration 为 300 秒。数据库会将过期任务标记失败；当前没有跨进程任务恢复和自动重试 worker。
- 预览和公开 VM 都是短期运行实例，8 分钟访问时效、9 分钟 VM 上限。稳定入口可重建过期实例。当前不包含长期容器托管、自定义域名绑定和完整 CDN 发布服务；不应将这版描述成已完成 Shopify 式生产托管。
- 本轮没有部署生产应用，没有配置公开数据 origin。发布入口与权限已实现，实际线上发布待部署接口后验证。
- 当前页面 DTO 最多包含 50 件商品；公开数据 API 自身支持分页，但生成页面的列表尚未接入分页交互。
- 网站参考图输入尚未支持；带图建站请求会明确提示先整理商品图片，不会静默忽略图片。

## 验证

- 全量 Vitest：67 个文件、504 项通过。
- TypeScript 检查通过。相关 ESLint 无错误；现有工作台图片及状态恢复仍有警告。
- PGlite 验证单网站、活动任务互斥、请求去重、跨组织拒绝、版本和取消隔离、编辑者发布权限、超时回收、发布历史及运行租约。
- 云端验证三表 RLS 开启、管理 RPC 仅 service_role 可执行，客户端不能读源码和运行凭据。
- 真实 Vercel Sandbox：固定测试组件通过 TypeScript、esbuild、SSR、访问控制。浏览器验证 hydration 按钮、列表/详情跳转和包含尖括号的数据安全序列化。
- 工作台和网站设计的浏览器状态测试使用拦截后的 API 响应，验证关键词分流、同网站后续修改、只读预览、手机宽度和未配置时禁用发布。
- 没有可用用户 DeepSeek Key，因此未执行真实模型生成收费请求；没有将固定测试组件当成真实 AI 生成结果。

复验：`npm run site:build:check`。该命令创建真实短期 Sandbox 并在结束时停止；仅用于验证编译和运行链路，不调用模型。
