# 工作台能力叠加

## 设计

使用统一工作台，不切换创作者和商家模式。内容能力显示内容、作品和选品入口；经营能力显示设计、商品和知识库；同时开通时同时显示两个分组。工作台、资料和设置共用。

消费者个人菜单按实际能力显示“成为内容创作者 / 管理内容”和“成为商家 / 管理商品”。工作台账号菜单提供尚未开通能力的入口。

开通流程：入口 → 填写名称 → 服务端确认当前用户并初始化共用组织、存储与项目 → 保存能力 → 返回统一工作台。追加能力沿用已有数据，不新建第二套空间。

## 状态

创作者使用服务端 app_metadata.creator_enabled。商家使用已有空间和 app_metadata.merchant_enabled；旧账户有空间且没有显式关闭标记时保持商家能力。创作者新开通的共用存储不等于已开通经营能力，因此保存 merchant_enabled=false；原有商家开通创作者时保留经营能力。

能力配置控制产品功能展示；所有数据读写继续由现有组织成员权限和 RLS 校验，隐藏导航不替代数据授权。此轮不引入付费角色和新的数据库表。

## 验收

普通用户、仅创作者、仅商家、双能力四种状态；追加开通保留旧能力；开通失败可重试，不跳转假成功；未经登录无法开通；已有账户兼容；手机与桌面导航一致。

## 实现与验证

- `/creator` 接创作者开通，`/merchant` 接商家开通，统一由 `/onboarding` 完成。
- 开通请求只接受 creator / merchant，并使用服务端验证的用户 ID。能力写入只经过服务端管理客户端。前端不提交可信权限。
- 创作者初始化前先保存未开通经营的标记，避免中断后重试将共用存储误认成经营能力。
- 已有项目不覆盖；组织与店铺初始化沿用原有幂等逻辑。此过程跨多个服务调用，不是原子事务；失败保留可重试状态，不宣称回滚。
- 单元测试覆盖四类账户、旧账户兼容、追加能力、部分初始化重试、无效类型、未登录和失败分支。
- 浏览器检查 390px / 1108px 的 creator、merchant、both 三种预览，导航和首页动作按能力显示，六组均无运行错误。
- TypeScript 检查通过；相关文件 ESLint 无错误，保留已有警告。
- 开通服务端测试使用模拟认证与存储；未创建云端账号或执行真实账号开通。本地预览不写入真实账号能力。
- 复用已有发布和经营功能，本轮不新增订单、结算等业务模块。

预览：`/preview/v3-ui?capability=creator`、`/preview/v3-ui?capability=merchant`、`/preview/v3-ui?capability=both`。

管理用户元数据的接口依据 [Supabase updateUserById 文档](https://supabase.com/docs/reference/javascript/auth-admin-updateuserbyid) 核对，管理凭据仅在服务端使用。
