# 记忆功能补充

沿用现有记忆表、确认状态机和上下文版本。本次没有建立第二份个人档案，也没有改变 Skill 启用条件。

## 已实现

- 成功提交已登录用户的普通对话回答后，通过 Next.js `after` 调度整理。
- 从服务端读取该账号最近 12 条用户消息，跨会话、按时间处理；不接收浏览器提供的历史作为记忆来源，不处理助手回答、图片观察或网页内容。
- 第一阶段仅提取独立、明确的第一人称喜好陈述，跳过引用、疑问、条件句、他人和临时需求。没有增加模型调用，不声称能归纳任意表达或心理特征。
- 同领域、同对象、同倾向的记忆复用原记录，最多保留 20 个消息来源引用。不能由重复次数自动确认。
- 同对象的相反倾向生成替代提案；确认前旧记忆保持有效。确认时检查原记录版本，变更过则要求重新审阅。只处理明确对象的相反倾向，不猜测语义冲突。
- 来源处理记录与提案写入同一事务，按账号加锁。重复任务不重复写入；删除后的已处理旧消息不会再次创建记忆。拒绝的同一陈述不会因另一次对话自动重新提案。
- 手动记忆 API 支持 `lifecycle: { subject: 'self' | 'other', scope: 'long-term' | 'temporary', expiresAt: ISO日期 | null }`。临时记忆必须设置有效截止时间，旧记录缺少该字段时按本人长期记忆兼容。
- 个人上下文排除他人记忆和已过期记忆。下次上下文读取时通过现有状态机使过期条目及依赖推断失效，递增上下文版本，让旧搜索续页失效。不是定时器在到期瞬间主动推送刷新。
- 手动修正内容后清除旧的自动冲突匹配字段，保留来源，避免继续用原句的匹配键判断新句。

## 边界

`after` 受部署函数生命周期与运行时长限制，不是持久任务队列。失败会记录无个人内容的日志，下次普通对话会重新扫描最近窗口。窗口之外的遗漏历史没有全量补扫承诺。本阶段不做模型生成的跨场景推断，不自动扩大到健康、外貌等专项信息。

提案在回答后生成，因此回答中的 `memoryProposed` 不提前声称已成功写入；现有记忆管理页面重新读取后可以审阅。尚未增加后台完成通知或时效编辑界面。

测试使用隔离的 PGlite 数据库实际执行迁移，验证跨会话去重、来源幂等、确认替代、旧版本拒绝、过期依赖失效和客户端角色权限。API 和单元测试覆盖适用范围、时效及后台调度。
