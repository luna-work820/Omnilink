# 内容发布与前端展示链路核查

结论：当前新版视频、图文和文章只连通本机内容管理，没有连通线上发布和消费者发现页。检查未修改业务源码，也未向线上发布测试内容。

## 当前链路

| 环节 | 状态 | 依据 |
| --- | --- | --- |
| 新版发布 → 本机内容管理 | 已连通 | `CreatorPublishingWorkspace.tsx:260` 与 `:269` 调用 `saveLocalPublication`，成功后进入管理页 |
| 本机存储 → 刷新与恢复编辑 | 已连通 | IndexedDB 保存内容、文件和封面；本轮实测刷新后测试记录仍存在 |
| 新版发布 → 正式内容接口 | 未连通 | 新旧页面都使用同一新版发布组件，该组件的发布函数没有调用 `/api/creator-posts` |
| 新版素材 → 服务器存储 | 未连通 | 新版发布记录保存的是浏览器 File 对象；没有调用已有私有视频上传接口 |
| 正式内容 → 发现页列表 | 未连通 | `app/discover/page.tsx:77` 将 `initialPosts` 固定为空数组 |
| 作品链接 → 按 ID 读取详情 | 未连通 | `components/consumer-market/App.tsx:81` 只在已有 `scenePosts` 中查找，不补充读取详情 |
| 新版文章 → 正式阅读组件 | 尚未适配 | 编辑器保存 BlockNote 内容；`CreatorPostReader` 仍按旧 ContentBlock 类型读取 |

## 具体断点

1. **P1：正式发布入口仍然只保存本机。** `app/dashboard/content/page.tsx` 与开发预览都渲染 `CreatorPublishingWorkspace`。登录仅改变 ownerKey，没有切换为服务器发布。管理页展示的“已发布”必须结合“本机预览”来源理解，不能据此判断其他用户可见。
2. **P1：发现页没有加载已发布作品。** 正式页面传入空 `initialPosts`，前端上下文通过该参数初始化作品列表。演示分支也只传入商品；`scenePostsList` 本身为空。已有数据库内容检索与搜索投影不等于首页作品列表接入。
3. **P1：新旧内容契约不一致。** 当前视频、图文、文章数据与旧接口 `{title, coverUrl, blocks, status}` 不同。旧接口写入 `kind: 'note'`，发布校验还要求至少一件已上架且具备外部链接的商品。新文章使用 BlockNote 段落、背景、封面位置及 `productLink` 部件；旧前端阅读器没有对应适配。直接替换保存方法无法完成接通。
4. **P2：发布设置尚未落到服务器。** 可见范围、保存权限、合集、声明、位置和定时等保存在本机对象内。旧正式接口不接受这些发布设置。当前定时只是管理页读取时检查时间并改写本机状态，不是服务器定时发布任务。

## 已有能力及验证范围

- 旧 `CreatorContentWorkspace` 已包含 POST/PATCH 内容保存、视频签名上传及稳定播放地址的接入代码。
- 旧 `/api/creator-posts` 包含身份与空间归属检查、草稿与公开版本隔离，并在发布后调用 `revalidatePath('/discover')`。
- 内容管理正式模式会读取旧接口并合并线上记录；开发预览只读取本机记录。管理页读取线上记录不意味着新版创建入口已使用该接口。
- 本轮运行：`npx vitest run lib/creator-content.test.ts app/api/creator-posts/route.test.ts app/api/creator-posts/media/route.test.ts 'app/api/creator-posts/media/[...path]/route.test.ts' lib/security/stage01-database.test.ts lib/security/stage45-database.test.ts`。
- 结果：6 个测试文件、34 项测试通过。范围是旧接口契约、视频访问、数据库权限及公开内容检索投影；不代表托管环境完成了端到端发布验收。

## 浏览器重放

1. 在独立的 `127.0.0.1` 开发来源打开图文发布页，选择项目已有图片。
2. 填写“发布连通核查测试”，确认弹窗明确显示内容保存到本机。
3. 点击“发布到本机预览”，内容管理出现一条已发布图文，来源为“本机预览”。
4. 刷新管理页，记录仍存在，可获得对应编辑链接及本机 ID。
5. 在演示发现页使用该 ID，标题匹配数为 0，对应内容详情弹层数为 0。此项为开发预览重放；正式页面的数据缺口由上述源码检查确认。
6. 测试记录已通过界面移入回收站。用户的 `localhost` 草稿和发布记录未写入本轮测试内容。

截图：`/tmp/omnilink-publication-wiring-audit.jpg`。浏览器日志仅出现既有月亮图标宽高比警告，没有发布接口运行错误；由于新版没有调用该接口，不能据此证明线上发布成功。

## 接通顺序

1. 先统一视频、图文、文章的正式内容契约，接入素材上传、草稿、发布与更新接口，并兼容已有线上记录。
2. 让发现页读取公开的已发布内容，增加按作品 ID 读取详情的路径；阅读器复用或适配新版文章渲染逻辑。
3. 在服务器落实可见范围与各项发布设置，明确定时发布的后台任务，再验收“发布账号创建作品 → 消费者列表看到作品 → 分享链接打开详情 → 编辑更新与下架同步”。
