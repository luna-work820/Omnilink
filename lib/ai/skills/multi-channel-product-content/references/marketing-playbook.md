# 营销手段层写法

按信息释放顺序组织内容的具体方法。层号越小，留人越强，也越靠近编造红线。生成抖音、小红书正文或设计开场前读取本文件。

## 通用原则

- 同一组商品事实，按所选层重排信息顺序，不新增、不改写事实取值。
- 层号只影响信息释放顺序、镜头顺序和开场设计，不影响文案说什么。
- 层与层的差别在结构，不在语气。换了层不等于换了说话方式。
- 任何层中出现商家未确认的场景、数字、体验，都属于编造，不是创意。
- 本文件的示例横跨多个品类，说明的是**结构**。实际产出必须用本次商品的字段替换，不要沿用示例里的品类。

## 第 1 层 前置钩子

开场与商品无关，用悬念把人留住，中段才揭示商品。

**结构**：0-3 秒无关开场 → 3-8 秒拉开关系 → 8 秒后揭示商品 → 卖点 → 收尾。

**开场素材来源**：只能取自商家确认的使用场景。把场景里最具体的一个瞬间当作开场，不要抽象概括。

开场只从商家确认的场景里挑。商家确认通勤、健身、办公室时，就不能写露营、下班回家、宿舍、咖啡馆、机场。

**回收要求**：开头抛出的悬念，正文必须明确接回。用一句「所以问题不是 X，是 Y」把开场和商品连起来，让悬念有落点。

**示例结构 A（家居用品，商家确认场景为「出租房厨房台面小」）：**

```text
0-3 秒  出租屋台面就那么大，锅具堆在一起永远找不到要找的那口。
3-8 秒  问题不是台面小，是收纳方式让常用的东西放在了最里面。
8 秒    这套就是挂起来用的，占的是墙面不是台面。
...     其余卖点
收尾    含两个挂钩，不含锅盖。
```

**示例结构 B（服饰，商家确认场景为「通勤挤地铁」）：

```text
0-3 秒  早高峰地铁上，两只手都占着。
3-8 秒  这种时候最烦的是包口太宽，东西一伸手就翻出来。
8 秒    这只包口收窄了，单手插进去能摸到要的那一样。
...     其余卖点
收尾    含隔层，不含内胆包。
```

**红线**：钩子本身必须真实可拍。做不到的场景不要写。

## 第 2 层 悬念递进

卖点分批释放，每批抛完给一句理由再进下一批。

**结构**：卖点 A → 为什么重要 → 卖点 B → 为什么重要 → 卖点 C → 收尾。

**递进顺序的排法**：不按卖点重要性排，按「用户从哪句话能想到下一句」排。常见顺序是从用户最容易理解的点进到难理解的点，从使用体验进到参数细节。

**示例结构（服饰，商家确认卖点为面料、版型、尺码）**：

```text
第一批  面料成分：棉 60%、聚酯纤维 40%。
理由    这决定洗几次之后会不会变形，日常穿脱频率高的场景最在意这条。
第二批  版型：直筒，不收腰。
理由    通勤坐下来不勒腰，这条决定它能不能进你每天的日程。
第三批  尺码：S/M/L 三档。
收尾    149 元，两色。
```

**注意**：递进不等于吊胃口。每批都必须给出这批的完整信息，不靠省略制造悬念。

## 第 3 层 痛点共鸣

先讲场景痛点，再引出商品如何解决。

**结构**：场景 → 具体麻烦 → 商品解决 → 其余卖点 → 收尾。

**痛点来源**：必须是商家确认的使用场景里真实存在的麻烦，不得想象消费者困境。

商家确认通勤、办公室时，痛点就只能写这两类场景里的麻烦。不得编造「送孩子上学」「露营时」等未确认场景。

**只有场景名时本层不成立**：商家确认「日常通勤」是场景名，不等于提供了具体麻烦。为了填痛点而想象消费者困境就是编造。此时二选一：

- 降级到场景内的信息选择负担，例如尺码、面料、参数是否写清楚，让人不必靠猜。这不引入新事实。
- 先与商家确认具体痛点，再回到本层。

不要因为写不出痛点就自行上移到第 5 层。层号由商家或渠道默认决定。

**示例结构（数码配件，商家确认场景为「出差要带很多线材」）**：

```text
痛点    出差要带三四根线，包里缠成一团，每次都理半天。
商品    这款是分格收纳，每根线各占一格。
其他    折叠后厚度 2cm，收纳包附赠。
收尾    89 元，不含数据线本体。
```

**层次选择**：这是抖音的默认层。信息量够、风险低，适合验证阶段使用。

## 第 4 层 对照评测

与同类横向对比参数档位。

**启用前提**：必须已有商家确认的对手事实。没有可比对手信息时禁用本层，改用第 3 层或第 5 层。

**对比维度**：只比商家双方都已确认且可比的参数。对比维度随品类变化：耐用品比耐用与售后参数，服饰比面料与版型，食品比配料与规格，家电比功率与能耗。不可跨品类对比。

**红线**：
- 不得贬低具体竞品或品牌。
- 不得做无依据的横向价格比较。「这个价位给这个配置的不少」这类表述没有可比依据，属违规。
- 不得暗示对比对象质量差，只能陈述参数差异。
- 对比结论必须来自可比参数本身，不能从参数推出「完胜」。

**示例结构**：

```text
A 款面料：100% 棉，价格 99 元。
本款面料：棉 60%、聚酯纤维 40%，价格 149 元。
差异在混纺比例和价格，其余配置按需比较。
```

比较完成后直接给差异，不下「完胜」「吊打」这类结论。

## 第 5 层 需求唤醒

直接介绍商品，靠商品本身说话。

**结构**：商品是什么 → 核心参数 → 适合谁用 → 收尾。

这是小红书和商品详情页的默认层。小红书允许上移到第 3 层，因为痛点共鸣在该平台最自然。

**小红书注意**：即使走第 5 层，也要分段、加口语节奏，避免读起来像参数表。标签和封面短句要贴合平台习惯。

**详情页注意**：核心卖点每条都要带事实依据，FAQ 只回答输入中有依据的问题，没有依据的问题不列。

## 跨层通用检查

每层产出后逐条过一遍：

- 开场或开场之后的所有场景，是否都能在商家确认的使用场景里找到。
- 是否有商家未确认的数字、时间、数量词。
- 是否有把商家实测改写成第一人称自测。
- 是否有无依据的量化承诺，包括把两个已确认事实相乘或相加得出的结论。
- 是否有贬低竞品或无依据横向比较。
- 是否误套了其他品类的槽位，例如给服饰填容量、给手机填净含量。
- 输入若是链接或页面截图，页面原文是否已按处置规则分类，是否有直接照抄的。
- 是否有商家说「可以写」但并未核对的项被当作确认取值。
- 事实层是否存在内部冲突未裁定。
- 第 1、2 层是否在正文回收了悬念。
