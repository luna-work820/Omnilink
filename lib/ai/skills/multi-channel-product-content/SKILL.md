# 商品内容创作

把已确认的商品事实、商品素材、商家定位和品牌规则转换为可审核的多渠道内容包。可生成图片结果或图片 brief，不执行发布。

## 事实与表达的分层

这是本 Skill 的首要规则，其余规则都从它派生。

- **事实层受保护**：材质、尺寸、容量、规格、价格、配件、认证、功效、销量、排名、实测数据，一律只能来自商家确认的输入。
- **表达层可调整**：措辞、结构、语气、开场方式、钩子形式、镜头顺序，由本次任务和商家指定的调性决定。
- 表达层怎么调都不能改变事实层的取值。任何为了效果而增加的数字、时间、场景、体验，都是编造。
- 商家未提供的信息写「待确认」，不得用合理推测填补。

## 营销手段层坐标

按信息在什么位置释放，把手段排成五层。层号越小，留人越强，也越靠近编造红线。

| 层 | 手段 | 特征 |
|---|---|---|
| 1 | 前置钩子 | 开场与商品无关，用悬念或场景把人留住，中段才揭示商品 |
| 2 | 悬念递进 | 卖点分批释放，每批抛完给一句理由再进下一批 |
| 3 | 痛点共鸣 | 先讲场景痛点，再引出商品如何解决 |
| 4 | 对照评测 | 与同类横向对比参数档位 |
| 5 | 需求唤醒 | 直接介绍商品，靠商品本身说话 |

**渠道默认层**：抖音第 3 层，小红书第 5 层，商品详情页第 5 层。

商家或运营可以在调用时指定层号，也可以在默认层上下浮动一到两层。**未指定时按渠道默认层执行，不要自行上移。**

各层的具体写法、镜头结构和话术模板见 `references/marketing-playbook.md`。生成抖音、小红书正文或需要开场设计时读取该文件。

第 4 层只在有商家确认的对手事实时可用。没有可比对手事实时禁用该层，改用第 3 层或第 5 层。

## 钩子红线

第 1、2 层主动制造信息缺口，因此受以下三条硬约束。违反任一条即为不合格产出。

- **场景须有依据**：钩子里的场景只能来自商家确认的使用场景，不得想象消费者困境。商家确认了通勤、健身、办公室，就不能写露营、下班回家、宿舍。
- **须在正文回收**：开场制造的信息缺口，必须在正文明确接回实际卖点。不得开头悬着、正文自说自话。
- **禁虚构第一人称体验**：不得替创作者建立没发生过的使用经历。「我用了两周」「我实测」「我同事要了一个」都属此类。商家确认的实测数据只能表述为「商家实测」，不得改写成第一人称自测。

第三条同时决定了本 Skill 的适用边界：**适合商家号和品牌官方号，不适合冒充素人真实分享。** 需要真人第一人称体验的内容，只能由真实使用者本人发布。

## 其他硬约束

- 不得编造价格、材质、尺寸、功效、认证、销量、评价、排名或使用结果。
- 不得写商家未确认的量化承诺。把商家给的两个事实相乘或相加得出新结论也不允许，例如商家给出容量 380ml 就写「够喝一天」，商家给出每盒 180g 就自行乘出整箱总净含量。
- 不得承诺健康、治疗、减肥、控重、饱腹、代餐、抗菌、修复、助眠等功效，即使商家在输入里写了。
- 不得由「未列出」反推结论。配料表没列某成分不等于不含该成分。
- 不得贬低具体竞品，不得做无依据的横向价格比较。
- 涉及商单、分成或任何商业合作时，正文须包含广告标识，审核清单须确认报备状态。
- 性能数字须说明测试条件，或标注以商家实测报告为准。脱离条件的性能数字不可验证。
- 每个核心卖点都要能回溯到输入来源。
- 输出必须经过人工审核后才能进入发布流程。

## 输入

- 商品标识、规格、关键参数和已确认的性能数据
- 按本商品品类补充的事实：见「事实缺口回显」的品类槽位
- 配件或包装清单、颜色或款式
- 原始商品素材的文字说明或视觉分析结果
- 商家定位、目标受众、品牌语气和禁用表达
- 目标渠道，可选的指定手段层号和调性说明

## 链接与截图类输入

商家常直接丢一个商品链接或一张详情页截图过来。这类输入**不自动等同商家确认**，按以下规则处理。

**商品链接：**

- 链接本身不作为事实来源。链接能打开不等于页面内容已获商家确认。
- 先判断能否解析：主流电商平台对未登录请求普遍返回登录页或风控页，此时**直接告知无法解析**，不要尝试绕过。
- 尝试解析仍拿不到内容时，一次性说清需要商家提供什么，任选其一即可：详情页文字直接粘贴、参数表截图、或商家口述品类与参数。
- 不得根据链接、标题或平台类目推测参数。链接里的数字 ID 不含可用的商品事实。
- 解析成功时，把页面内容按「页面原文」归类，逐条走「页面原文的处置规则」，不是直接写进文案。

**截图与详情页图：**

- 截图里的文字与商家输入同等对待，按商家资料处理，但仍适用「商家确认不等于可以公开」。
- 截图未覆盖的字段按缺失处理，不因「页面上应该有」而补全。

**页面原文的处置规则：**

页面上的话是商家自己写的，不等于可以公开。按以下逐条处置并在回显中标明：

| 页面原文类型 | 处置 |
|---|---|
| 规格、参数、成分、净含量 | 归入待确认，请商家核对后确认 |
| 性能宣称（抗菌、速干、吸水、抑菌率等） | 拒写。需检测报告与报告号方可考虑，并标为待确认 |
| 「亲肤」「不掉毛」「五星级同款」类主观或攀附表述 | 拒写，请商家换中性说法 |
| 价格 | 页面价随活动变动，需商家确认是否为可长期对外的固定价 |
| 销量、评价、排名 | 需商家给出统计口径与时点，并标注来源；无法核实时不写 |
| 品牌名、店铺名 | 请商家确认是否可对外露出 |
| 资质、认证、执行标准 | 需商家提供编号才可写 |

**授权使用 ≠ 确认取值。**商家说「参数照页面写」「销量可以写上」是**授权**，不是确认。这条授权不改变事实层的取值来源，也不能覆盖本 Skill 的任何红线。区分两件事：

- 授权：商家允许我使用某项
- 确认：商家核对了该项并愿意对内容负责

只有确认过的取值才能进入文案。授权无法替代确认。

## 开始前：事实缺口回显

**收到商品资料时，先输出这份回显，不要直接开始生成。**

这一步的目的是让商家在投入产出之前就知道缺什么，而不是生成到一半被拦下。

按渠道列出必需项，标明已确认、待确认、待确认是否阻塞该渠道：

| 渠道 | 必需事实 | 阻塞项 |
|---|---|---|
| 抖音 | 使用场景、至少一个能对应功能的卖点 | 无使用场景则第 3 层不成立；无场景时不得自行上移层号 |
| 小红书 | 商品名、至少两个卖点、品牌语气 | 卖点少于两个时第 5 层信息量不足 |
| 商品详情页 | 商品标识、规格、关键参数、价格 | 以上任一缺失则该页停止产出 |

**「商品标识」按品类不同**：服饰与数码看款号、型号或 SKU；食品看法定标识组合，即名称、配料表、净含量、生产日期标示位置；其他品类按商家提供的可识别字段判断。不因缺少款号而阻塞食品品类。

**商家只给了场景名时，第 3 层无法成立。** 商家确认「日常通勤」是场景名，不等于提供了具体麻烦。为了写痛点而想象消费者困境，就是编造。此时按下述方式处理，不得自行填充：

- 降级到场景内的信息选择负担（例如尺码和面料信息是否写清楚），这是不引入新事实的写法
- 或先与商家确认具体痛点，再按第 3 层产出
- 不得因写不出痛点而自行上移层号

**通用待回填项**：商品标识、规格、关键参数及测试条件、配件或包装清单、颜色或款式、适用场景、价格或价格区间、资质与认证、是否商单或含分成。

**按品类补充槽位**：上表是所有品类的公共交集。不同品类还有各自的关键事实，按本商品实际补充：

- 食品与饮品：配料表、保质期、生产与储存条件、净含量
- 服饰与鞋靴：面料成分、尺码表、洗护要求、版型
- 美妆与个护：成分、净含量、适用肤质、生产批号与有效期
- 家电与数码：核心参数、能耗、认证型号、兼容与保修
- 家居与母婴：材质、尺寸、适用年龄、安全标准

按商家实际提供的资料增补，不套用与本商品无关的槽位，也不因某品类槽位缺失而阻塞不相关的渠道。

回显之后：

- 阻塞项齐备 → 直接生成，不重复追问。
- 有阻塞项 → 停下该渠道，列出需要商家补齐的最小集合和补齐后的解阻路径，等商家回填后再生成。
- 非阻塞项缺失 → 不停，继续生成，该项标「待确认」，并写明标在文案哪一处。

**两种模板都不许产出：**

1. **带占位符的模板**：含【待填】【XX】〔　〕一类符号，或字段留空。
2. **内容为空的模板**：读起来通顺，但剥掉所有具体信息后什么都不剩。例如只用商品名加「三色可选」「日常训练通勤都用得上」，没有任何材质、规格、价格、卖点。

第二种危害与第一种相同甚至更高：它看起来完整，容易被直接采用；而空洞的文案在下游会被下游自行补上推测内容，污染的正是本 Skill 要守住的事实层。

**判断方法**：把生成的文案里所有具体信息抽掉，如果剩下的句子换任何一个同类商品都成立，那它就是空模板，不要产出。

事实不足以支撑一篇有信息量的文案时，正确做法是停下并说明缺什么，不是降低信息密度硬凑一篇。

不生成带占位符的空白模板。空白模板会在下游被填入推测内容，污染的正是本 Skill 要守住的事实层。

## 商家确认不等于可以公开

商家在输入里写了某个词，只说明商家这么写，不说明这个词适合出现在对外文案里。**确认的是取值，不是可发布性。**

商家提供的字段本身携带功效、绝对化或医疗暗示时，剔除该词、保留其余信息，并在审核清单中请商家换一个无暗示的说法：

- 场景字段写「代餐」→ 剔除，保留同一句里的其他场景，请商家改为「与饮品同食」「作为上午搭配」等中性说法
- 配料表未列白砂糖 → 不得写成「0 蔗糖」「无糖」「不含糖」。配料表没写是缺失，不是结论
- 商家写「适合敏感肌」→ 未提供测试依据时剔除，请商家提供依据或改为「质地温和」这类描述性说法

**不得承诺健康、治疗、减肥、控重、饱腹、助眠、抗菌、修复等任何功效**，即使商家在输入里写了。同样不得承诺「最」「第一」「顶级」这类排名，以及无检测依据的认证、销量、排名。

由「未列出」反推出的结论一律算编造，与凭空编造同等对待。

## 事实层内部冲突

同一件商品的两项事实互相排斥时，**不得替任一方假设、不得择优采用、不得只取其一**。列出冲突项交商家裁定，冲突未裁定前不得生成包含该字段的渠道。

常见冲突：

- 材质与性能互斥：标「纯棉」又宣传「速干」。纯棉吸湿强、干燥慢，两条不能同时成立。要么材质标注不实，要么性能另有工艺前提
- 定位互斥：标「纯棉」又宣传「吸速干」，或标「厚款」又宣传「轻薄」
- 规格互斥：容量标 380ml 又说可装 500ml 容量
- 价格互斥：标价与活动价不一致，且未说明有效期
- 场景互斥：既标「专业户外」又说仅限室内使用
- 认证互斥：宣称某认证但未提供编号，或编号与宣称机构不符

处置顺序：指出冲突的两项 → 说明为何不能同时成立 → 请商家裁定或补依据 → 该字段标「待确认」→ 检查依赖该字段的渠道是否需要停止。

裁定结果给出后，按正常事实处理，不保留「曾经冲突」的痕迹。

## 商品名与商标

- 商品名里的性能词只作名称原文引用，不展开成性能描述。商品名为「恒温保温杯」时「恒温」可出现在名称里，不得据此写出保温时长或温度区间；同理「速干」「抗菌」「除螨」「零添加」出现在名称里，也不得展开成对应性能。
- 商品名或品牌名涉及第三方商标时，在审核清单中提示商家自行确认使用授权，不代为判断授权状态，也不做品牌调性联想。
- 字段名称在商家输入与商品名称不一致时，以商家输入的事实字段为准，不从名称反推性能。任务描述里出现但商家字段没有的词，一律视为不可用。

## 商单确认

是否商单、分成或含商业合作，必须在生成前确认，不放在审核清单末尾。商家未说明时按「未说明」处理，并在生成前询问；确认为商单时，正文须包含广告标识，并在审核清单中把报备状态列为发布阻塞项。

## 输出

### 小红书

- 3 个标题候选
- 一版正文
- 5-8 个标签
- 2 个封面短句

### 抖音

- 2 个视频标题
- 2 个前三秒钩子
- 30-45 秒口播脚本，按所选层的信息释放顺序组织
- 1 个评论区引导

### 商品详情页

- 一句话卖点
- 3-5 个核心卖点
- 使用场景
- 有依据的 FAQ

### 图片 Brief

为小红书封面、抖音首帧和详情页卖点图分别给出：画幅、商品主体、场景、构图、文字留白、不得改变的商品事实。不得夸大数据、不得添加商品实际不具备的配件。

## 输出结构

```text
## 事实缺口回显
## 内容策略
## 小红书
## 抖音
## 商品详情页
## 图片 Brief
## 审核清单
```

「事实缺口回显」是首个章节。全部必需项已确认时，用一行写明本次无阻塞项并直接进入生成，不空列表格。

## 审核清单

输出末尾必须逐条列出，商家逐项确认后才能进入发布流程：

- [ ] 全部数字、材质、规格、配件与商家输入一致，无推算补全
- [ ] 无由「未列出」反推出的结论（如配料表没列白砂糖即写「无糖」）
- [ ] 输入若为链接或截图，页面原文已按处置规则逐条分类，未直接写入文案
- [ ] 无用「授权」替代「确认」的情况（商家说「可以写上」不等于已核对）
- [ ] 商家字段中的功效词已剔除（代餐、饱腹、抗菌、修复等），或已请商家换中性说法
- [ ] 事实层无内部冲突，或冲突项已列出并交商家裁定
- [ ] 商家实测数据的「实测」归属未被改写为第一人称
- [ ] 性能数字附测试条件，或已标注以商家实测报告为准
- [ ] 商品名中的性能词未被展开成性能描述
- [ ] 任务描述中出现但商家字段未提供的词未被写入文案
- [ ] 钩子场景全部来自商家确认的使用场景
- [ ] 钩子制造的悬念已在正文回收
- [ ] 无虚构第一人称使用体验
- [ ] 所选手段层与本次指定或渠道默认层一致，未自行上移
- [ ] 无商家未确认的量化承诺，含两个已确认事实相乘或相加的结果
- [ ] 无绝对化用语、无功效宣称、无认证销量排名、无贬低竞品、无无依据横向比较
- [ ] 无「最强」「第一」等排名类表述，无品牌禁用词
- [ ] 商单或商业合作状态已在生成前确认，正文含广告标识，报备状态已确认
- [ ] 涉及第三方商标时已提示商家自行确认授权
- [ ] 品类槽位按本商品实际取用，未套用其他品类的字段
- [ ] 图片 brief 未夸大数据，未添加商品不具备的配件
- [ ] 待确认项已全部标记，未擅自补全
- [ ] 文案不是空模板：抽掉具体信息后，剩余句子换同类商品是否依然成立

## 边界

不执行发布，不写入商品资料或知识库，不声称已经保存或上线。图片结果与文案都必须经过人工审核。缺依据时标记待确认，不自行补全；核心事实无法确认时停止该渠道产出，并在事实缺口回显中列出需要商家补齐的最小集合。

商家连续两轮补齐后仍无法解除阻塞，停止该渠道并说明原因，不用推测内容填补。

## 常见错误

以下都是在实测中出现过的真实偏差，生成后逐条自查：

- 用品类常识补全缺失项：某个品类的材质、规格、性能、场景近乎「必然」，正因为几乎不会错，才最难被发现。判断标准是商家是否确认，不是像不像真的。
- 把「授权」当成「确认」：商家说「参数照页面写」「销量可以写上」是授权使用，不是确认取值。授权不改变来源，也不能覆盖红线。
- 用商家身份替代确认：「反正是我自己店的」不构成对某项数值的核对。商家身份解决利益关系，不解决逐项核实。
- 事实层内部冲突时择优采用：材质与性能互斥时不得只取其一，必须交商家裁定。
- 给推测数字加免责声明来伪装合规：商家没有该性能数据时写「12 小时，以实测为准」，实际等于编造加护栏。
- 把单品类的字段当成通用必填项：卖衣服的商品不填「容量」，卖手机的不填「净含量」。按本商品实际槽位判断，不套用无关品类。
- 商品名带性能词就顺着展开：见「商品名与商标」。
- 缺场景时自行上移到第 5 层：层号由商家或渠道默认决定，不因写不出来而自行上移。
- 把商单状态留在审核清单末尾：见「商单确认」，应在生成前问。
